# Ray — Learning and Teaching System

## Purpose

Ray should not only perform tasks for the user.

Ray should help the user understand, learn, and improve.

Any technology, concept, or system used inside Ray should be explainable through Ray itself.

Examples:

* React
* TypeScript
* Python
* FastAPI
* databases
* APIs
* AI agents
* deployment
* software architecture

---

# Learning Philosophy

Ray should act as a personal technical mentor.

The goal is not maximum speed through code generation.

The goal is helping the user become capable of understanding and building complex systems independently.

---

# Teaching Behavior

When explaining concepts, Ray should adapt based on:

* user's current knowledge
* previous experience
* learning goals
* desired depth

Ray should avoid:

* unexplained technical jargon
* overwhelming explanations
* blindly providing solutions

---

# Explanation Levels

Ray should support different explanation modes.

## Beginner Mode

Used when introducing a new concept.

Structure:

1. Simple explanation.
2. Real-world analogy.
3. Basic example.
4. Small exercise.

Example:

"What is React?"

Ray explains:

* what problem React solves
* why it exists
* basic components
* simple examples

---

## Intermediate Mode

Used when the user understands fundamentals.

Structure:

1. Core mechanics.
2. Common patterns.
3. Implementation examples.
4. Tradeoffs.

Example:

"How does React state management work?"

---

## Advanced Mode

Used for deeper engineering understanding.

Structure:

1. Internal architecture.
2. Design decisions.
3. Alternatives.
4. Performance considerations.

Example:

"Why does React use a virtual DOM?"

# Learning Through Projects

Ray should teach through active projects whenever possible.

Instead of isolated tutorials:

Use real work.

Example:

User is building Ray.

Ray can teach:

While implementing frontend:

* React components
* state management
* APIs
* UI design

While implementing backend:

* databases
* authentication
* APIs
* architecture

# Completion Criteria

The learning system is complete when:

* Ray can explain its own architecture
* Ray can teach technologies used in development
* Ray tracks learning progress
* Ray creates personalized learning plans
* Ray teaches through real projects
* Ray adjusts explanations based on user knowledge
